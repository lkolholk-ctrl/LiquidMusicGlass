1. ОБЗОР
--------------------------------------------------------------------------------
API для встраивания поиска и проигрывания музыки в сторонние приложения.

База: https://byicloud.online
API-ключ: pk_<id>_<random> — выдаётся при подключении.


2. АВТОРИЗАЦИЯ
--------------------------------------------------------------------------------

2.1 API-ключ
  Заголовок: X-Partner-Key: pk_...
  Формат: pk_<partner_id>_<32-char-secret>

2.2 Partner User ID
  Заголовок: X-Partner-User-Id: <stable-user-id>
  Нужен для: /library/*, /me/*, аналитика, per-user настройки.
  Макс 128 символов.

2.3 Session-токен (для клиентских запросов)
  Выпускается бэкендом партнёра через POST /session/issue.
  Использование: Authorization: Bearer <token>
  Жизнь: 1 час (expires_in секунд).
  Не клади в localStorage — XSS-вектор.
  Не дёргай /session/issue на каждый запрос — кешируй.

2.4 CORS
  Нужен ТОЛЬКО для browser direct (client-direct) запросов.
  Для server-to-server и мобильных приложений CORS не нужен.
  Указывай полный origin: https://yourdomain.com

2.5 Модели авторизации

  | Сценарий          | Кто стучится       | Авторизация           | CORS |
  |-------------------|--------------------|-----------------------|------|
  | Server-to-server  | Твой backend → API | X-Partner-Key         | Нет  |
  | Client-direct     | Браузер → API      | partner_session_token | Да   |
  | Мобильный/натив   | Приложение → API   | Token или API Key     | Нет  |


3. ЭНДПОИНТЫ
--------------------------------------------------------------------------------

3.1 GET /health
  Response:
    {
      "partner_id": "yourname",
      "status": "active",
      "scopes": ["search", "stream", "album", "artist", "meta", "lyrics"],
      "rate_limits": {
        "search": {"rpm": 600, "burst": 60},
        "stream": {"rpm": 1200, "burst": 120}
      },
      "stream": {
        "max_quality": "256K",
        "allowed_sources": ["primary", "secondary"],
        "signed_url_ttl_seconds": 600
      },
      "search": {"max_results": 30, "regions_allowed": ["us", "ru"]},
      "server_time": 1747200000
    }

  allowed_sources — источники, доступные партнёру.

3.2 GET /search
  Параметры:
    q       — Строка поиска. Макс 200 символов. Минимум 2 alphanumeric.
              Пустые запросы → 400 query_too_short.
              Мусор ≥10/мин → 429 query_spam_detected.
    region  — us/ru/nz. Должен быть в regions_allowed.
    source  — primary (default) / secondary / all.
              secondary/all требует чтобы secondary был в allowed_sources.
    limit   — Макс результатов. Клампится до config.search.max_results.

  Response items — три типа сущностей. Различай по флагам:
    isArtist=true   → Артист
    isAlbum=true    → Альбом/плейлист
    оба false       → Трек

  Поля результата:
    id            — ID сущности
    title         — Название трека/альбома или имя артиста
    artist        — Исполнитель трека
    artistId      — ID артиста
    cover         — URL шаблон обложки (1000x1000 → 300x300)
    preview       — 30-секундное превью (треки только)
    collectionId  — ID альбома (треки) или same-as-id (альбомы)
    album         — Название альбома (треки)
    is_explicit   — true если 18+
    duration      — Длительность в МИЛЛИСЕКУНДАХ (треки)
    isCustom      — true для собственных релизов инди-артистов
    region        — Фактически использованный регион

  Региональная подмена: если запрошенный регион не разрешён,
  подменяется на первый из regions_allowed.

  End-to-end:
    1) GET /search?q=believer → берём track id
    2) POST /track с trackId → получаем url для стрима

3.3 POST /track
  Request body:
    {
      "trackId": "<id>",
      "region": "us",
      "quality": "256K"
    }

  Response:
    {
      "track_id": "<id>",
      "file_id": "<internal-id>",
      "source": "primary|secondary|custom|special",
      "quality": "256K",
      "artist_id": "<artist-id>",
      "url": "https://byicloud.online/api/partner/audio/<file_id>?ps=<sig>&pid=<partner>",
      "expires_at": 1747200600
    }

  Quality: 128K / 256K / 320K / ALAC (первичный каталог)
           MP3 256K / MP3 320K (вторичный каталог)
  URL действует ~600 секунд.

  Ошибки:
    451 region_unavailable — retry с required_region
    403 source_not_allowed — source отключён в конфиге
    404 track_not_found — не найден ни в одном регионе
    403 early_access — релиз ещё не вышел (пресейв)

3.4 GET /audio/{file_id}
  Прямой стрим URL из поля url ответа /track.
  Авторизация через query-параметр ps, заголовки не нужны.
  Поддерживает Range: bytes= (seeking).
  Content-Type: audio/mp4 (primary) или audio/mpeg (secondary).
  Cache-Control: public, max-age=604800 (1 неделя).

  Когда URL истёк (403 invalid_or_expired_signature):
    Перевызови POST /track с тем же trackId — кеш сработает, ответ мгновенно.

3.5 GET /album/{id}
  Query: ?region=us
  Response:
    {
      "album": {
        "id": "<id>",
        "title": "...",
        "artist": "...",
        "artistId": "...",
        "cover": "<url-template>",
        "type": "Album|Single|EP|playlist",
        "year": 2017,
        "trackCount": 11,
        "description": "...",
        "motionCoverUrl": "<animated-cover-url>"
      },
      "tracks": [
        {
          "id": "<track-id>",
          "title": "...",
          "artist": "...",
          "cover": "...",
          "collectionId": "<album-id>",
          "duration": 199853,
          "is_explicit": false,
          "trackNumber": 1
        }
      ]
    }

  type="playlist" — для редакционных плейлистов (id начинается с pl.)
  motionCoverUrl — анимированная обложка mp4 (опционально)

3.6 GET /artist/{id}
  Query: ?region=us
  Response:
    {
      "id": "<id>",
      "name": "...",
      "cover": "...",
      "bio": "...",
      "followers": 1234567,
      "genre": "...",
      "topSongs": [...],
      "singles": [...],
      "albums": [...],
      "featuring": [...],
      "similarArtists": [...],
      "latestRelease": {...}
    }

  Поля:
    topSongs       — Топ-20 треков
    singles        — Синглы
    albums         — Полноформатные альбомы (дедуплицированы)
    featuring      — Альбомы с фичером
    similarArtists — Похожие артисты
    latestRelease  — Самый свежий релиз (любого типа)

3.7 GET /track/{id}/meta
  Метаданные без stream URL.
  Response: id, collectionId, title, artist, cover, duration

3.8 GET /cover-sign
  Query: ?file_id=<id>
  Для custom-обложек, требующих подписи.
  Response: { "url": "<signed>", "expires_at": <timestamp> }


4. ВТОРИЧНЫЙ КАТАЛОГ (Secondary Catalog)
--------------------------------------------------------------------------------

4.1 Включение
  Требуется "secondary" в stream.allowed_sources (настраивается админом).
  Если отключён: 403 source_not_allowed.

4.2 ID-префиксы
  secondary_track_<id>  — Трек
  secondary_artist_<id> — Артист
  secondary_album_<id>  — Альбом

  Префиксы выдаются в /search, /album, /artist.
  Резолвер определяет каталог по префиксу автоматически.

4.3 Поиск
  ?source=secondary — только вторичный каталог.
  ?source=all — объединяет первичный + вторичный (первичный первым).

4.4 Stream
  Тот же POST /track endpoint. Префикс определяет резолвер.
  Quality: MP3 256K (default) или MP3 320K (для подписчиков).
  Параметр region игнорируется.

4.5 Единицы измерения duration
  ВАЖНО: Первичный каталог возвращает duration в МИЛЛИСЕКУНДАХ.
         Вторичный каталог возвращает duration в СЕКУНДАХ.
  Клиент ДОЛЖЕН нормализовать: если duration < 1000, умножить на 1000.

4.6 Альбом / Артист
  Структура ответа идентична первичному каталогу.
  Поля: topSongs, singles, albums, featuring, similarArtists, latestRelease.

4.7 Ограничения
  - Lyrics и batch /tracks/meta не поддерживаются.
  - Нет региональной привязки.
  - ALAC недоступен (макс MP3 320K).
  - Первый запрос холодного трека: 3–10 сек (подготовка файла).
    Используй ?async=1 (см. раздел 10).


5. ТЕКСТЫ ТРЕКОВ (LYRICS)
--------------------------------------------------------------------------------

5.1 GET /track/{id}/lyrics
  Query: ?region=us (опционально)
  Response:
    {
      "track_id": "<id>",
      "source": "primary",
      "format": "lrc",
      "lyrics": "[00:00.00] First line...\n[00:08.34] Second line..."
    }

  Альтернатива: GET /lyrics?track_id=<id>&region=us

  Поддерживается: первичный каталог, премиум треки.
  Custom треки: всегда 404 lyrics_not_found.

  Первый запрос холодного трека: до 10 сек.
  Последующие: мгновенно из кеша.

5.2 LRC-формат
  [mm:ss.xx] Текст строки
  Теги: [ti:title], [ar:artist], [al:album], [offset:ms]

7. МЕДИАТЕКА (/library/*)
--------------------------------------------------------------------------------
  Требует: linked user (X-Partner-User-Id).
  Ошибка: 403 user_not_linked если не привязан.

7.1 GET /library/likes
  Query: ?source=primary|secondary|all&limit=50&offset=0
  Response:
    {
      "count": 12, "total": 12, "offset": 0, "limit": 50,
      "items": [
        {
          "id": "<track-id>",
          "trackId": "<track-id>",
          "title": "...", "artist": "...", "cover": "...",
          "duration": 204347,
          "collectionId": "<album-id>",
          "artistId": "<artist-id>",
          "is_explicit": false,
          "liked_at": 1747200000
        }
      ]
    }

7.2 GET /library/subscriptions
  Query: ?source=... (так же как likes)
  Response items:
    {
      "id": "<artist-id>",
      "name": "Artist Name",
      "image": "<url>",
      "isCustom": false,
      "isPremium": true
    }

7.3 GET /library/wave/next
  Персональная радиостанция / волна.
  Query параметры:
    exclude       — ID треков через запятую (текущая очередь)
    seed_track_id — Создать станцию на основе этого трека
    recent_skips  — Количество подряд пропущенных (skip-streak fallback)
    region        — Регион

  Response:
    {
      "track": {
        "id": "<track-id>", "title": "...", "artist": "...",
        "cover": "...", "duration": 204347,
        "collectionId": "<album-id>", "artistId": "<artist-id>",
        "is_explicit": false
      },
      "status": "ok",
      "region": "us"
    }

  status:
    ok    — Трек найден и готов
    empty — Нет кандидатов (юзер ничего не лайкал или всё исключено)

  Вызывай повторно для построения непрерывной очереди.
  Предзагружай 3-5 треков вперёд для бесшовного воспроизведения.
  Scope: library_wave.

7.4 POST /library/wave/feedback
  Body:
    {
      "feedback_type": "less_track|less_artist|less_genre|more_track|more_artist|more_genre",
      "value": "<track-id|artist-id|genre-name>"
    }

  UI mapping:
    👍 Больше этого трека   → more_track + track_id
    👎 Меньше этого трека  → less_track + track_id
    👍 Больше этого артиста → more_artist + artist_id
    👎 Меньше этого артиста → less_artist + artist_id

  Забывание: half-life 30 дней. Повторные клики идемпотентны.

7.5 POST /library/wave/playback
  Логирование прослушивания для улучшения ранжирования.
  Body:
    {
      "track_id": "<id>",
      "played_seconds": 180.5,
      "total_seconds": 204.3,
      "completed": true,
      "skipped": false
    }

  Поля:
    track_id        — Обязательно. ID трека из /library/wave/next.
    played_seconds  — Обязательно. Фактическое время прослушивания.
    total_seconds   — Рекомендуется. Длительность трека.
    completed       — Авто: played >= 0.85 * total
    skipped         — Авто: played < 0.15 * total

  Вызывать при: окончании трека, скипе, переключении.
  logged=true если записано. logged=false для треков не из первичного каталога.
  Scope: library_wave_playback.

7.6 POST /library/wave/reset
  Очищает историю волны, seed-артистов, предпочтения.
  Лайки сохраняются.
  Response: { "status": "ok", "removed": 142 }

7.7 GET /library/wave/popular-artists
  Для онбординга — список популярных артистов на выбор.
  НЕ требует partner_user_id.
  Кешируется 24ч на сервере.
  Response: [ { "id": "...", "name": "...", "image": "..." } ]

7.8 GET /library/wave/onboarding
  Статус онбординга.
  Response: { "artists": [...], "completed": true }

7.9 POST /library/wave/onboarding
  Сохранение выбора артистов.
  Body: { "artists": [ { "id": "...", "name": "..." } ] }
  Минимум 1, рекомендуется 3-5.
  Response: { "ok": true, "saved": 2 }


8. BATCH-ЗАПРОСЫ
--------------------------------------------------------------------------------
POST /tracks/meta
  Body: { "track_ids": ["id1", "id2", "id3", ...] }
  Макс 50 track IDs за запрос.
  Response:
    {
      "count": 3,
      "items": [
        { "id": "...", "title": "...", "artist": "...", "cover": "...", "duration": 199853 },
        { "track_id": "...", "error": "not_found" },
        ...
      ]
    }

  Занимает 1 meta rate-limit hit вместо N.
  Не поддерживается для вторичного каталога.


9. ASYNC-РЕЖИМ ДЛЯ /track
--------------------------------------------------------------------------------
  Добавь ?async=1 к POST /track.
  Для холодных треков, требующих подготовки файла (1-5 сек, ALAC до 1 мин).

  Тёплый трек → Обычный 200 с url.
  Холодный трек → 202 Accepted:
    {
      "job_id": "a3f5b1c20d8e4f72",
      "status": "pending",
      "poll_after_seconds": 3
    }

  Проверка: GET /track/job/{job_id}
  Pending → { "status": "pending", "poll_after_seconds": 3 }
  Ready   → { "status": "ready", "track": { ...full /track response... } }

  Job истекает через 10 минут.
  Не полли чаще чем poll_after_seconds.

12. ЛИМИТЫ
--------------------------------------------------------------------------------

Группы rate limits (считаются отдельно):
  search        — /search
  stream        — /track
  session_issue — /session/issue
  default       — /album, /artist, /meta, /cover-sign, /lyrics,
                  /me/*, /library/* (включая /library/wave/playback)

/audio и /cover стримы НЕ считаются в лимиты.
Точные значения в /health.

12.1 Что кешировать
  /search              — 60 сек по (query + region)
  /album/{id}          — 24+ часа
  /artist/{id}         — 24+ часа
  /track/{id}/meta     — 24+ часа
  file_id из /track    — 24+ часа по (trackId + region + quality)
  partner_session_token — До expires_in

12.2 Что НЕ кешировать
  url из /track      — Живёт ~10 минут
  url из /cover-sign — Живёт ~10 минут
  /audio/{file_id}   — Браузер кеширует сам (1 неделя)

12.3 Расчёт на 100k DAU
  /search:  1-2 rpm (кеш)
  /track:   10-20 rpm (всплески при старте)
  /album, /artist, /meta: Единицы rpm


13. СТРИМИНГ: ЛУЧШИЕ ПРАКТИКИ
--------------------------------------------------------------------------------

13.1 Жизненный цикл URL
  1. POST /track с trackId → получаешь url + expires_at
  2. Подставляешь url в плеер
  3. На 403/expired: повторный POST /track (кеш, мгновенно)

13.2 File ID
  file_id из /track можно кешировать на 24+ часа.
  Одинаковый trackId + region + quality = одинаковый file_id.

13.3 Quality
  max_quality в /health капает запросы.
  Подписчики могут переопределять через /me/preferences.
  Явный quality в /track имеет наивысший приоритет.

13.4 Region
  Если регион не из regions_allowed → автозамена.
  Проверяй поле region в ответе.
  451 region_unavailable → retry с required_region.

13.5 Интеграция плеера
  HTTP Range requests поддерживаются (seeking).
  Content-Type: audio/mp4 (primary) или audio/mpeg (secondary).
  Позволь плееру автоопределять формат — НЕ хардкодь MIME.


14. X-REQUEST-ID
--------------------------------------------------------------------------------
  Каждый ответ содержит заголовок X-Request-Id.
  Указывай его при обращении в поддержку.


15. ВЕРСИОНИРОВАНИЕ API
--------------------------------------------------------------------------------
  Текущая: v1 (неявно в /api/partner)
  Breaking changes анонсируются за 30 дней.
  Добавления (новые поля, эндпоинты) — backward-compatible.


16. ПРИМЕЧАНИЯ ПО ДАННЫМ
--------------------------------------------------------------------------------

16.1 Duration
  Первичный каталог: МИЛЛИСЕКУНДЫ
  Вторичный каталог: СЕКУНДЫ
  Нормализация: if duration < 1000 → duration * 1000

16.2 Cover URLs
  Первичный каталог: шаблоны с размерами
    1000x1000 — полное разрешение
    600x600   — среднее
    300x300   — thumbnail
  Заменяй в строке URL напрямую.

16.3 Explicit
  is_explicit на треках.
  Если hide_explicit=true — фильтруй из поиска и альбомов.

16.4 Custom релизы
  isCustom=true — собственные релизы инди-артистов.
  ID формата custom_album_123 или просто число.
  Работают так же — через /track.
