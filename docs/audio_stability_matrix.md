# Матрица стабильности аудио: причины лагов/«циклички» и их статус

«Цикличка» = AAudio/MMAP крутит последний заполненный буфер по кругу, когда
приложение перестаёт вовремя отдавать данные. Лаги = underrun'ы (пропуски
буфера). Ниже — систематический перечень ВСЕХ известных причин по слоям
аудио-тракта и что с каждой сделано. При новых жалобах — идти по этой таблице
сверху вниз, сверяясь с телеметрией `JUCE.xruns` в DebugLog.

Тракт: файл → декод (MediaCodec/JUCE reader, read-ahead поток) →
BufferingAudioSource (предчтение) → AudioTransportSource → аудио-коллбэк
(микс + FX) → Oboe/AAudio → микшер ОС. Стриминг: сеть → ExoPlayer → AudioTrack.

## A. Голодание realtime-коллбэка

| # | Причина | Статус |
|---|---------|--------|
| A1 | CPU-шторм системного UI (шторка, переключение приложений) | ✅ Буфер динамика 6×burst (~30мс); адаптивная эскалация до 8× по xrun-телеметрии; BT всегда 8× |
| A2 | Тяжёлый код в коллбэке (FX-цепочка, IIR) | ✅ Всегда -O2 (в т.ч. debug); bass-swap биквады только в переходе; FX пропускает выключенные стадии |
| A3 | Блокирующие локи в коллбэке | ✅ Только tryEnter пер-дековых локов + hold-блок (1 замещающий блок с фейдом); позиция — lock-free атомики |
| A4 | Аллокации в коллбэке | ✅ Скретч-буферы преаллоцированы в audioDeviceAboutToStart |
| A5 | Энергосбережение (Battery Saver) жёстче тротлит CPU | ✅ setPowerSaveMode: буфер сразу 8×burst на время режима |

## B. Голодание декода (буфер транспорта осушается → рывки/цикличка)

| # | Причина | Статус |
|---|---------|--------|
| B1 | Read-ahead потоки не получают CPU под нагрузкой | ✅ Priority::highest (ниже RT Oboe); по потоку на дек |
| B2 | Малое предчтение | ✅ mp3/aac 8с, wav/flac 5с |
| B3 | WakeLock истекает через 10 мин непрерывной игры → CPU в дрёме | ✅ **Ключевой фикс фона**: manageWakeLock() из цикла полинга (500мс) перезахватывает истёкший lock |
| B4 | Мёртвый кодек (codec reclaimed/internal error) → вечный цикл декода | ✅ Страж: фатальный статус/2с без прогресса → одна реанимация кодека с текущего кадра, иначе EOS |
| B5 | Doze душит фоновые потоки процесса | ✅ Пункт настроек «Ignore Battery Optimization» (REQUEST_IGNORE_BATTERY_OPTIMIZATIONS) |
| B6 | Тяжёлый AutoMix-анализ (декод 2 треков + FFT) на общем CPU-пуле за ~40с до конца каждого трека | ✅ Весь анализ на ОДНОМ потоке THREAD_PRIORITY_BACKGROUND (AutoMixController.analysisDispatcher) |

## C. Управляющий путь блокирует аудио

| # | Причина | Статус |
|---|---------|--------|
| C1 | Глобальный JNI-мьютекс сериализовал всё (load блокировал pause/позицию) | ✅ shared_ptr-снапшот; мьютекс только на копию указателя |
| C2 | Бесконечный цикл в offline-декоде (prepareStretchB) вешал вызывающий поток | ✅ Тот же страж, что B4 |
| C3 | Гонки init/route-reopen/release с разных потоков | ✅ deviceControlMutex (аудио-коллбэк его не берёт) |
| C4 | Ожидание main из load-потока навсегда | ✅ runOnMainBlocking с таймаутом 10с |

## D. Жизненный цикл потока/устройства

| # | Причина | Статус |
|---|---------|--------|
| D1 | Смена маршрута BT↔динамик — пачки событий, циклы реопенов | ✅ Debounce 700мс + dedup в AudioRouteMonitor; BT — крупный буфер без fast-path |
| D2 | AAudio DISCONNECTED (рестарт audioserver) | ⚠️ Полагаемся на реопен JUCE/Oboe + наш route-монитор; при жалобах — проверить логи на Disconnected |
| D3 | Потеря аудио-фокуса (транзиент/дак) | ✅ Дак с дебаунсом 250мс (пачки LOSS↔GAIN от других приложений давали «цикличку» громкости) |

## E. Уровень процесса (фон)

| # | Причина | Статус |
|---|---------|--------|
| E1 | Сервис теряет foreground → cached → freezer морозит процесс (цикличка), потом LMK | ✅ Media3 MediaSessionService держит foreground по состоянию плеера (JUCE отдаёт BUFFERING/READY корректно); wakelock см. B3 |
| E2 | LMK убивает процесс по памяти | ✅ onTrimMemory: сброс memory-кэша Coil (был до 30% heap) и кэша лирики |
| E3 | Doze откладывает сеть → стриминг ребуферится в фоне | ✅ ExoPlayer WAKE_MODE_NETWORK (wake+wifi lock на время игры; было LOCAL — WiFi засыпал) + B5 |

## F. UI мешает аудио косвенно (CPU/GPU/GC)

| # | Причина | Статус |
|---|---------|--------|
| F1 | Полноэкранный fbm-дым + AGSL-плитки давят GPU/CPU | ✅ DeviceTier.lite: 4 октавы + все клоки 30Гц; энергосбер: градиент 15Гц, бас-пульс выключен; заморозка при потере фокуса окна (EffectsLifecycle) |
| F2 | Линковка AGSL-программ на холодном старте (давала ANR) | ✅ Отложенный прогрев по кадрам, по одной программе за кадр |
| F3 | getState() маппит весь плейлист каждые 500мс → мусор/GC на main | ✅ Кэш MediaItemData по identity плейлиста |
| F4 | Пер-кадровые корутины (бас-пульс) в фоне/на паузе | ✅ Останавливаются на паузе; в фоне кадров нет (Choreographer) |

## G. Диагностика (когда что-то новое)

1. `JUCE.xruns +N (total=…)` в DebugLog — есть ли underrun'ы вообще и когда.
2. `JUCE.xruns escalate buffer (#1)` — сработала ли адаптация; помогла ли
   (перестал ли счётчик расти после).
3. Если xrun'ов НЕТ, а рывки есть — проблема НЕ в коллбэке: смотреть декод
   (B) — позиция замирает? — или стриминг/сеть (E3).
4. «Цикличка» = коллбэк перестал отдавать данные ЦЕЛИКОМ (заморозка процесса,
   E1) либо hold-блок при частых промахах лока (C) — сверить с моментами
   заморозки/фокуса.
5. Perfetto: `perfetto -c` с категориями `audio sched freq` покажет тайминги
   AAudio-коллбэка и тротлинг наших потоков на таймлайне.
