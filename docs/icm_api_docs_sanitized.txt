1. OVERVIEW
--------------------------------------------------------------------------------
API for embedding music search and playback into third-party applications.

Base URL: https://byicloud.online
API Endpoint Prefix: /api/partner


2. AUTHENTICATION
--------------------------------------------------------------------------------

2.1 API Key
  Header: X-Partner-Key: pk_<partner_id>_<32-char-secret>
  Format: pk_<id>_<random>
  Issued on partner onboarding.

2.2 Partner User ID
  Header: X-Partner-User-Id: <stable-user-id>
  Required for: /library/*, /me/*, analytics, per-user settings
  Max 128 characters.

2.3 Session Token (for client-direct requests)
  Issue endpoint: POST /session/issue
  Headers for issuance: X-Partner-Key + Content-Type: application/json
  Request body:
    {
      "partner_user_id": "u_42",
      "hide_explicit": false
    }
  Response:
    {
      "partner_session_token": "<JWT>",
      "expires_in": 3600,
      "partner_user_id": "u_42",
      "scopes": ["search", "stream", "album", "artist", "meta"]
    }
  Client usage: Authorization: Bearer <token>
  Do NOT expose API key in frontend — use session tokens.

2.4 CORS
  Only needed for browser direct (client-direct) requests.
  Server-to-server and mobile apps do NOT need CORS.
  Provide full origin: https://yourdomain.com


3. ENDPOINTS
--------------------------------------------------------------------------------

3.1 GET /health
  Response:
    {
      "partner_id": "yourname",
      "status": "active",
      "scopes": ["search", "stream", "album", "artist", "meta"],
      "rate_limits": {
        "search": {"rpm": 600, "burst": 60},
        "stream": {"rpm": 1200, "burst": 120}
      },
      "stream": {
        "max_quality": "256K",
        "allowed_sources": ["primary", "secondary"],
        "signed_url_ttl_seconds": 600
      },
      "search": {"max_results": 30, "regions_allowed": ["us", "ru"]},
      "server_time": 1747200000
    }

3.2 GET /search
  Query parameters:
    q           — Search string, max 200 chars, min 2 alphanumeric
    region      — us/ru/nz (must be in regions_allowed)
    source      — primary / secondary / all
    limit       — Max results, clamped to config.search.max_results

  Response items types (distinguish by flags):
    isArtist=true   → Artist entity
    isAlbum=true    → Album/playlist entity
    both false      → Track entity

  Item fields:
    id              — Entity ID
    title           — Track/album title or artist name
    artist          — Track artist name
    artistId        — Artist identifier
    cover           — Cover art URL template (resize: 1000x1000 → 300x300)
    preview         — 30-second preview URL (tracks only)
    collectionId    — Album ID (tracks) or same as id (albums)
    album           — Album name (tracks only)
    is_explicit     — true if explicit content
    duration        — Duration in MILLISECONDS (tracks only)
    region          — Actual region used (may differ from request)

  Important: Use debounce 300ms. Cache by (q + region) for 60s.

3.3 POST /track
  Request body:
    {
      "trackId": "<id>",
      "region": "us",
      "quality": "256K"
    }

  Response:
    {
      "track_id": "<id>",
      "file_id": "<internal-file-id>",
      "source": "primary|secondary|custom|special",
      "quality": "256K",
      "artist_id": "<artist-id>",
      "url": "https://byicloud.online/api/partner/audio/<file_id>?ps=<signature>&pid=<partner>",
      "expires_at": 1747200600
    }

  Quality options: 128K, 256K, 320K, ALAC
  Default region: us
  URL validity: ~600 seconds (see signed_url_ttl_seconds in /health)

  Errors:
    451 region_unavailable — retry with required_region from response
    403 source_not_allowed — source disabled in partner config
    404 track_not_found — not found in any region

3.4 GET /audio/{file_id}
  Direct stream URL from /track response.
  No auth headers needed — signature is in query param.
  Supports Range: bytes= requests (seeking).
  Returns audio/mp4 or audio/mpeg depending on source.
  Cache-Control: public, max-age=604800 (1 week)

  When URL expires (403 invalid_or_expired_signature):
    Re-call POST /track with same trackId — cache hit, response in milliseconds.

3.5 GET /album/{id}
  Query: ?region=us
  Response:
    {
      "album": {
        "id": "<id>",
        "title": "...",
        "artist": "...",
        "artistId": "...",
        "cover": "<url-template>",
        "type": "Album|Single|EP|playlist",
        "year": 2017,
        "trackCount": 11,
        "description": "...",
        "motionCoverUrl": "<animated-cover-url>"
      },
      "tracks": [
        {
          "id": "<track-id>",
          "title": "...",
          "artist": "...",
          "artistId": "...",
          "cover": "...",
          "collectionId": "<album-id>",
          "duration": 199853,
          "is_explicit": false,
          "trackNumber": 1
        }
      ]
    }

  Playlist IDs start with "pl." — same endpoint, type="playlist".
  Custom releases: isCustom=true, id format custom_album_123.

3.6 GET /artist/{id}
  Query: ?region=us
  Response fields:
    id, name, cover, bio, followers, genre
    topSongs      — Array of tracks
    singles       — Array of tracks
    albums        — Array of albums (full-length, deduplicated)
    featuring     — Albums where artist is featured
    similarArtists — Related artists
    latestRelease — Most recent release (any type)

  All nested IDs use same prefix system as search results.

3.7 GET /track/{id}/meta
  Metadata without stream URL.
  Response: id, collectionId, title, artist, cover, duration

3.8 GET /cover-sign
  Query: ?file_id=<id>
  For custom covers that need signed URLs.
  Response: { "url": "<signed-url>", "expires_at": <timestamp> }

  Primary catalog covers use direct URLs — no signing needed.


4. SECONDARY CATALOG
--------------------------------------------------------------------------------

4.1 Enabling
  Requires "secondary" in stream.allowed_sources (admin setting).
  If disabled: 403 source_not_allowed for all secondary requests.

4.2 ID Prefixes
  secondary_track_<id>    — Track
  secondary_artist_<id>   — Artist
  secondary_album_<id>    — Album

4.3 Search
  ?source=secondary returns secondary catalog results.
  ?source=all merges primary + secondary (primary first).

4.4 Track Stream
  Same POST /track endpoint. Prefix tells resolver which catalog.
  Quality: MP3 256K (default) or MP3 320K (for linked subscribers).
  Region parameter is ignored for secondary catalog.

4.5 Duration Units
  IMPORTANT: Secondary catalog returns duration in SECONDS.
  Primary catalog returns duration in MILLISECONDS.
  Client MUST normalize: if duration < 1000, multiply by 1000.

4.6 Artist Response Fields
  Same structure as primary catalog artist, plus:
    singles, featuring, bio, followers

4.7 Limitations
  - Lyrics and batch /tracks/meta not supported for secondary catalog.
  - No regional binding.
  - ALAC quality not available (max 320K MP3).
  - First request for cold track: 3–10 seconds (file preparation).
    Use ?async=1 to avoid blocking (see section 10).


5. LYRICS
--------------------------------------------------------------------------------

5.1 GET /track/{id}/lyrics
  Query: ?region=us (optional)
  Response:
    {
      "track_id": "<id>",
      "source": "primary",
      "format": "lrc",
      "lyrics": "[00:00.00] First line...\n[00:08.34] Second line..."
    }

  Alternative: GET /lyrics?track_id=<id>&region=us

  Supported: primary catalog tracks (cached), some premium tracks.
  Custom tracks: always 404 lyrics_not_found.

  First request for cold track: up to 10 seconds.
  Subsequent: instant from cache.
  Scope required: lyrics.

5.2 LRC Format
  Synced: [mm:ss.xx] Lyric text
  Tags: [ti:title], [ar:artist], [al:album], [offset:ms]

7. LIBRARY (/library/*)
--------------------------------------------------------------------------------
  Requires: linked user (X-Partner-User-Id header).
  Errors: 403 user_not_linked if not linked.

7.1 GET /library/likes
  Query: ?source=primary|secondary|all&limit=50&offset=0
  Response:
    {
      "count": 12,
      "total": 12,
      "offset": 0,
      "limit": 50,
      "items": [
        {
          "id": "<track-id>",
          "trackId": "<track-id>",
          "title": "...",
          "artist": "...",
          "cover": "...",
          "duration": 204347,
          "collectionId": "<album-id>",
          "artistId": "<artist-id>",
          "is_explicit": false,
          "liked_at": 1747200000
        }
      ]
    }

7.2 GET /library/subscriptions
  Query: ?source=... (same as likes)
  Response items:
    {
      "id": "<artist-id>",
      "name": "Artist Name",
      "image": "<url>",
      "isCustom": false,
      "isPremium": true
    }

7.3 GET /library/wave/next
  Personal radio / discovery station.
  Query parameters:
    exclude         — Comma-separated track IDs to exclude (current queue)
    seed_track_id   — Create station based on this track
    recent_skips    — Number of consecutive skips (skip-streak fallback)
    region          — Region override

  Response:
    {
      "track": {
        "id": "<track-id>",
        "title": "...",
        "artist": "...",
        "cover": "...",
        "duration": 204347,
        "collectionId": "<album-id>",
        "artistId": "<artist-id>",
        "is_explicit": false
      },
      "status": "ok",
      "region": "us"
    }

  status values:
    ok     — Track found and ready
    empty  — No candidates (user hasn't liked anything or all excluded)

  Call repeatedly to build continuous radio queue.
  Preload 3-5 tracks ahead for seamless playback.
  Scope: library_wave.

7.4 POST /library/wave/feedback
  Body:
    {
      "feedback_type": "less_track|less_artist|less_genre|more_track|more_artist|more_genre",
      "value": "<track-id|artist-id|genre-name>"
    }

  UI mapping:
    👍 More this track   → more_track + track_id
    👎 Less this track   → less_track + track_id
    👍 More this artist  → more_artist + artist_id
    👎 Less this artist  → less_artist + artist_id

  Decay: 30-day half-life. Repeated clicks are idempotent.

7.5 POST /library/wave/playback
  Log playback event for ranking improvement.
  Body:
    {
      "track_id": "<id>",
      "played_seconds": 180.5,
      "total_seconds": 204.3,
      "completed": true,
      "skipped": false
    }

  Fields:
    track_id        — Required. Track ID from /library/wave/next.
    played_seconds  — Required. Actual listening time accumulated.
    total_seconds   — Optional but recommended. Track duration.
    completed       — Optional. Auto-calculated: played >= 0.85 * total
    skipped         — Optional. Auto-calculated: played < 0.15 * total

  Call when: track ends, user skips, or switches tracks.
  logged=true in response if signal recorded.
  logged=false for non-primary track IDs (secondary catalog tracks ignored).
  Scope: library_wave_playback.

7.6 POST /library/wave/reset
  Clears wave history, seed artists, preferences.
  Likes are preserved.
  Response: { "status": "ok", "removed": 142 }

7.7 GET /library/wave/popular-artists
  For onboarding UI — list of popular artists to select from.
  Does NOT require partner_user_id.
  Cached 24h on server.
  Response: [ { "id": "...", "name": "...", "image": "..." } ]

7.8 GET /library/wave/onboarding
  Check onboarding status.
  Response: { "artists": [...], "completed": true }

7.9 POST /library/wave/onboarding
  Save user's artist selection.
  Body: { "artists": [ { "id": "...", "name": "..." } ] }
  Minimum 1, recommended 3-5.
  Response: { "ok": true, "saved": 2 }


8. BATCH REQUESTS
--------------------------------------------------------------------------------
POST /tracks/meta
  Body: { "track_ids": ["id1", "id2", "id3", ...] }
  Max 50 track IDs per request.
  Response:
    {
      "count": 3,
      "items": [
        { "id": "...", "title": "...", "artist": "...", "cover": "...", "duration": 199853 },
        { "track_id": "...", "error": "not_found" },
        ...
      ]
    }

  Consumes 1 meta rate-limit hit instead of N.


9. ASYNC MODE FOR /track
--------------------------------------------------------------------------------
  Add ?async=1 to POST /track request.
  For cold tracks that need file preparation (1-5 seconds, ALAC up to 1 minute).

  Warm track → Normal 200 with url.
  Cold track → 202 Accepted:
    {
      "job_id": "a3f5b1c20d8e4f72",
      "status": "pending",
      "poll_after_seconds": 3
    }

  Poll: GET /track/job/{job_id}
  Pending → { "status": "pending", "poll_after_seconds": 3 }
  Ready   → { "status": "ready", "track": { ...full /track response... } }

  Job expires after 10 minutes.
  Do NOT poll more frequently than poll_after_seconds.

12. RATE LIMITS
--------------------------------------------------------------------------------

Groups (counted separately):
  search        — /search
  stream        — /track
  session_issue — /session/issue
  default       — /album, /artist, /meta, /cover-sign, /lyrics,
                  /me/*, /library/* (including /library/wave/playback)

/audio and /cover streams do NOT count against limits.
Exact values in /health response.

12.1 What to Cache
  /search              — 60 seconds by (query + region)
  /album/{id}          — 24+ hours
  /artist/{id}         — 24+ hours
  /track/{id}/meta     — 24+ hours
  file_id from /track  — 24+ hours by (trackId + region + quality)
  partner_session_token — Until expires_in

12.2 What NOT to Cache
  url field from /track     — Expires in ~10 minutes
  url field from /cover-sign — Expires in ~10 minutes
  /audio/{file_id} files    — Browser caches automatically (1 week)

12.3 Estimate for 100k DAU
  /search:  1-2 rpm (cached)
  /track:   10-20 rpm (spikes on player start)
  /album, /artist, /meta: Single-digit rpm


13. STREAMING BEST PRACTICES
--------------------------------------------------------------------------------

13.1 URL Lifecycle
  1. Call POST /track with trackId → get signed url + expires_at
  2. Feed url directly to player
  3. On 403/expired: re-call /track (cache hit, instant response)

13.2 File ID Caching
  file_id from /track response can be cached for 24+ hours.
  Same trackId + region + quality always returns same file_id.

13.3 Quality Parameter
  Partner config max_quality caps user requests.
  Linked subscribers can override via /me/preferences.
  Explicit quality param in /track takes highest priority.

13.4 Region Handling
  If requested region not in regions_allowed → auto-substituted.
  Always check region field in response.
  451 region_unavailable → retry with required_region.

13.5 Player Integration
  Supports HTTP Range requests (seeking).
  Content-Type: audio/mp4 (primary) or audio/mpeg (secondary).
  Let player auto-detect format — do NOT hardcode MIME type.


14. X-REQUEST-ID

16. DATA MODEL NOTES
--------------------------------------------------------------------------------

16.1 Duration Normalization
  Primary catalog: duration in MILLISECONDS
  Secondary catalog: duration in SECONDS
  Client normalization: if duration < 1000 → multiply by 1000

16.2 Cover URL Templates
  Primary catalog covers use size templates:
    1000x1000 → full resolution
    600x600   → medium
    300x300   → thumbnail
  Replace in URL string directly.

16.3 Explicit Content
  is_explicit flag on tracks.
  If partner config hide_explicit=true or user preference set,
    filter explicit tracks from search and album listings.

16.4 Custom Releases
  isCustom=true indicates independent artist releases.
  IDs may be numeric or custom_album_123 / custom_track_123 format.
  Work identically in /track, /album, /artist endpoints.
