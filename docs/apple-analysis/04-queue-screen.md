## 1. Структура списка

Очередь — это **отдельная страница плеера** (не bottom-sheet поверх), одна из трёх: `SONG / LYRICS / QUEUE`. Экран состоит из:

1. **Мини-плеер сверху** (не скроллится): обложка/видео-сюрфейс, название, исполнитель, кнопка «сердце». Это и есть «сейчас играет» — **играющий трек в самом списке отсутствует**.
2. **Закреплённый (sticky) заголовок секции** — отдельный `FrameLayout` над списком; при скролле старый заголовок выталкивается новым (iOS-подобный push), а не просто заменяется.
3. **Список** (`RecyclerView`, вертикальный `LinearLayoutManager`, `ListAdapter` + DiffUtil).
4. **Транспорт-контролы внизу**, поверх списка; под ними список гасится анимированным градиентом (снизу чёрный fade, интерполяторы Decelerate/Accelerate).

### Разделы списка, сверху вниз

| Раздел | Что внутри | Заголовок | Откуда данные |
|---|---|---|---|
| **История** | недавно проигранные треки (строки `small_list_d_history_item`) | `header_queue_history` — **только как sticky**, обычной строкой-заголовком в списке его нет | из медиатеки (history-плейлист), а не из очереди плеера |
| **Playing Next** (пользовательская очередь) | треки, добавленные вручную («Play Next» / «Add to Queue») | `header_queue_section`: заголовок + кнопка очистки справа | элементы, у которых метаданные помечены `IS_IN_QUEUE_SECTION` |
| **Продолжение источника** | остаток альбома/плейлиста, из которого играем | `header_queue_up_next`: статичный титул + **живой подзаголовок** («продолжаем из ‹название плейлиста›») | всё, что не queue-секция и не автоплей |
| **Autoplay** | треки, подобранные автоматически | `header_queue_autoplay` | элементы с меткой `IS_FROM_CONTINUOUS_PLAYBACK` |
| **Футер-индикатор «ещё N песен»** | одна строка `number_of_song_indicator` | — | показывается **только если впереди >100 треков**; текст = plural на (остаток − 99) |
| **Футер режима повтора** | строка `repeat_mode_indicator_message` | — | показывается только при включённом repeat |
| **Пустая очередь** | строка `empty_upnext_message` | — | вместо всех секций, когда впереди ничего нет |

Счётчиков вида «12 треков» у заголовков **нет**. Единственные «числа» — футер «ещё N песен» (>100) и текст про repeat, который собирается из (заголовок контейнера, число повторяемых треков, число треков в пользовательской очереди).

**Порядок секций задаётся не UI, а самим таймлайном**: UI просто идёт по очереди от текущего индекса вперёд, размечает каждый элемент тремя типами и вставляет заголовок в момент смены типа. Заголовков поэтому ровно столько, сколько реально есть непустых секций.

**Особый случай**: если впереди остались *только* автоплей-треки, вместо заголовка «Autoplay» показывается заголовок `header_queue_up_next` с другим подзаголовком (объясняющим, что дальше идёт автоподбор). То есть Apple не показывает «Autoplay» как отдельную секцию, когда автоплей — это вообще всё, что осталось.

**Лимит**: движок очереди отдаёт наверх максимум **100 предстоящих элементов** (`maxUpcomingItemsCount = 100`). Остальное — числом в футере.

## 2. Управление

### Перетаскивание
- **Тянут за ручку (drag handle) справа в строке**, а не за строку. Long-press по строке перетаскивание **не** запускает (`isLongPressDragEnabled` = false); `onTouch` по ручке на `ACTION_DOWN` вызывает `startDrag`.
- Ручка появляется **только в режиме редактирования** — флаг приходит из сессии (`EXTRA_CAN_EDIT_QUEUE`). Когда редактировать нельзя, ручка не исчезает, а становится `INVISIBLE` (место сохраняется — строки не «прыгают»).
- Направления перетаскивания: вверх/вниз. Свайп: влево и вправо (оба).
- **Ограничения дропа** (`canDropOver`): переставлять можно только внутри своей секции; единственный разрешённый переход через границу — трек из секции «остаток источника» можно затащить **вверх, в пользовательскую очередь**. Обратно и автоплей-треки через границы не ходят. SharePlay-строки не перетаскиваются и не свайпаются вообще.
- **Автоскролл при перетаскивании** заклампован: вверх выше первой строки-трека список не проматывается — в историю утащить нельзя.
- **Во время перетаскивания:**
  - список переставляется **локально** (`Collections.rotate` подсписка + `notifyItemMoved`) — плеер не трогается;
  - над и под тащимой строкой рисуются два градиентных «теневых» подтона;
  - строка визуально приподнимается (в биндинг-компоненте плеера: масштаб → 0.85, рост cardElevation, 300 мс, DecelerateInterpolator);
  - строка не отрисовывается, если ушла выше заголовка секции;
  - **TalkBack** получает `AccessibilityEvent` с текстом «переместил вверх/вниз ‹название трека›».
- **Команда плееру уходит один раз — на отпускании** (`clearView`), а не на каждый шаг. Позиция адаптера конвертируется в позицию очереди вычитанием количества нетрековых строк (заголовки, история, футеры) до этой позиции. Затем шлётся кастомная сессионная команда `MOVE_QUEUE_ITEM` с тремя аргументами: id источника, id цели и тип цели — `MOVE_BEFORE_TARGET`, если тащили на самый верх (сразу после играющего), иначе `MOVE_AFTER_TARGET`.

### Удаление
- **Свайп в любую сторону** по строке. Отдельной кнопки-крестика нет.
- Под строкой открывается **сплошная цветная (деструктивная) подложка** с иконкой корзины, прижатой к тому краю, откуда «уезжает» строка (зеркалится при свайпе в другую сторону).
- Свайп включён только в режиме редактирования (тот же `EXTRA_CAN_EDIT_QUEUE`).
- Действие немедленное: `REMOVE_QUEUE_ITEM` по queue-id элемента. **Undo/снэкбара с отменой нет.**
- Играющий трек удалить нельзя — его в списке нет.

### Очистка
Две **разные** очистки, обе через подтверждение:

1. **Очистка пользовательской очереди** — кнопка в заголовке `header_queue_section`. Открывается вертикальный action-sheet: заголовок + деструктивный пункт + «Отмена». Подтверждение шлёт `ACTION_CLEAR_QUEUE_SECTION`. Движок удаляет **только элементы окна queue-секции** — играющий трек, остаток альбома/плейлиста и автоплей остаются на месте.
2. **Очистка истории** — кнопка в заголовке `header_queue_history`. Свой отдельный action-sheet, чистит history-плейлист в медиатеке. Кнопка неактивна, если история пуста; обе кнопки прячутся (`INVISIBLE`), если медиатека ещё не готова.

## 3. Добавление: «Play Next» vs «Add to Queue»

Обе операции — одна и та же сессионная команда `ADD_QUEUE_ITEMS`, различается только `INSERTION_TYPE`:

| Действие | Тип вставки | Куда реально попадает |
|---|---|---|
| **Play Next** | `AFTER_CURRENT_ITEM` (3) | сразу после играющего = **в самое начало** пользовательской очереди |
| **Add to Queue / Play Last** | `AT_END_OF_QUEUE_SECTION` (10) | в **конец пользовательской очереди**, но всё ещё **перед** остатком альбома/плейлиста и перед автоплеем |

То есть «в конец» у Apple — это конец *своей* секции, а не конец всей очереди. Треки, добавленные вручную, никогда не оказываются за остатком плейлиста.

**Как показано, что трек добавлен вручную:** отдельного бейджа на строке нет. Признак — **принадлежность к секции «Playing Next»**, и только она. Метка живёт в метаданных элемента (`IS_IN_QUEUE_SECTION`), а на стороне движка — как окно `QueueSectionWindow [start, end]` в плоской очереди.

**Обратная связь после добавления:** снэкбар внизу с иконкой и текстом — разный для «play next» и «added to queue», короткая длительность, **весь снэкбар кликабелен**: тап разворачивает плеер и переключает его на страницу очереди. Снэкбар не показывается для автоплей-вставок и когда режим уведомления вставки это запрещает.

**Побочный эффект:** добавление в очередь при «умном» шаффле выключает шаффл.

## 4. Автопродолжение (аналог нашей волны)

- Подобранные треки приходят отдельным провайдером (`AutoPlayPlaybackQueueItemProvider`, containerType = 6) и **дописываются в хвост очереди**. Каждый элемент помечен `IS_FROM_CONTINUOUS_PLAYBACK`.
- В списке они **отделены собственным заголовком** `header_queue_autoplay` и идут строго последней секцией.
- **Отличий в самой строке нет** — те же обложка/название/артист/ручка. Разделение чисто секционное.
- Если впереди ничего кроме автоплея — заголовок подменяется на «up next» с поясняющим подзаголовком (см. §1).
- **При включённом repeat автоплей-треки исчезают из списка полностью** — и из UI (фильтр перед построением секций), и из движка (такие элементы считаются непроигрываемыми). Логика: «зациклили — значит подбор не нужен».
- Переключатель автоплея есть в контролах плеера (иконка ∞), состояние хранится тремя значениями (недоступно / выкл / вкл); доступность приходит из сессии (`CAN_SET_CONTINUOUS_PLAYBACK`).

## 5. Открытие, закрытие, скролл

- **Открывается** кнопкой очереди в контролах плеера. Это `replace` фрагмента внутри плеера с **shared-element переходом** (обложка + видео-сюрфейс перетекают между страницами). Кнопка **тоггл**: повторный тап по «очереди» возвращает на страницу Now Playing. Также очередь открывается тапом по снэкбару «добавлено в очередь».
- **Стартовая позиция скролла:** при открытии/раскрытии шторки список программно скроллится так, чтобы **первый заголовок секции оказался ровно у верхней кромки**. История, соответственно, лежит выше и достаётся скроллом вверх — она не мозолит глаза, но и не потеряна.
- **Смена трека:** таймлайн пересобирается, DiffUtil-адаптер накатывает разницу (сравнение по queue-id для идентичности, по названию/артисту/обложке — для содержимого), и после завершения анимаций элементов список **снова прижимается к первому заголовку секции**. То есть при переходе на следующий трек очередь сама «подъезжает» к началу нового «Playing Next».
- **Сохранение позиции прокрутки:** состояние LayoutManager кладётся в `onSaveInstanceState` **только при смене конфигурации** (поворот) и хранится в статическом поле; восстанавливается ровно один раз, после чего сбрасывается. При обычном закрытии/открытии очереди позиция **не** восстанавливается — работает правило «к первому заголовку».
- Все перестроения списка ставятся в очередь на `ItemAnimator.isRunning(callback)` — обновления не наезжают на идущие анимации; во время enter-перехода апдейты копятся в очередь и проигрываются после.
- Метрика страницы называется `UpNext`, событие показа — `NowPlaying → UpNext`.

## 6. Мелочи, заметные в использовании

- **Играющий трек нельзя ни перетащить, ни удалить** — его физически нет в списке (список строится от текущего индекса и первый элемент отбрасывается). Он живёт в мини-плеере сверху.
- **Тап по строке очереди** — прыжок на этот трек (поиск по queue-id в таймлайне + `seekToDefaultPosition`), а не «вставить следующим».
- **Тап по строке истории** — либо навигация на трек, либо (если можно допендить в очередь) добавление; поведение зависит от флага `CAN_PREPEND_TO_QUEUE` из сессии.
- **Пустая очередь**: специальная строка-сообщение, но она показывается **не всегда**. Она скрывается, если играет лайв-радио, включён repeat, включён автоплей — **или если автоплей для этой очереди вообще недоступен**. Фактически сообщение появляется только в честном тупике: автоплей доступен, но выключен, повтора нет — то есть это подсказка «включи автоплей».
- **Explicit-бейдж** дорисовывается к названию трека.
- **Обложка меняет соотношение сторон**: 16:9 для видеотипов (клипы, шоу), 1:1 для музыки.
- **Фон строки** переключается между двумя цветами в зависимости от того, тёмная ли текущая палитра обложки; цвет-подложка обложки берётся из метаданных (`ARTWORK_BACKGROUND_COLOR`).
- **Окно пользовательской очереди всегда начинается сразу после играющего**: при смене трека `startIndex` пересчитывается в `current + 1`; когда съеден последний ручной трек, окно схлопывается и секция «Playing Next» исчезает сама.
- Кнопка `button_add_to_queue` в адаптере есть, но в этой сборке она недоделана (показывает тост «Media Picker is WIP») и ни одним элементом списка не создаётся.
- Есть лэйаут `spacer_upnext_last_item` — нижний отступ, чтобы последний трек не прятался под контролами; сам `RecyclerView` дополнительно получает bottom-padding, равный высоте блока контролов.

## Правила, которые стоит перенести

1. **Играющий трек — не строка списка.** Он в закреплённой шапке. Тогда вопросы «а можно ли его удалить/перетащить» отпадают сами.
2. **Три источника треков — три секции с заголовками**: ручная очередь → остаток источника → автоподбор. Порядок секций выводится из самой очереди, заголовок вставляется в момент смены типа. Пустых заголовков не бывает.
3. **Признак «добавлено вручную» — это принадлежность к секции, а не бейдж на строке.** Держать окно `[start, end]` пользовательской секции в модели очереди; при смене трека сдвигать `start = current + 1`; при схлопывании — сбрасывать.
4. **«Играть следующим» = начало ручной секции, «в конец очереди» = конец ручной секции**, а не конец всей очереди. Иначе ручной трек попадает за 40 треков альбома и пользователь его не увидит.
5. **Тянуть только за ручку**, long-press не занимать под drag. Ручку показывать/прятать через `INVISIBLE`, чтобы строки не дёргались.
6. **Команду перестановки слать один раз, на отпускании.** Во время drag двигать только локальный список. Это убирает дребезг плеера и рассинхрон.
7. **Запрещать дроп через границы секций**, с единственным исключением «поднять трек из источника в ручную очередь».
8. **Клампить автоскролл** — не давать утащить строку выше первого трека/в историю.
9. **Sticky-заголовок с выталкиванием**: следующий заголовок подпирает текущий и выдавливает его — дешёвый эффект, который сразу читается как «Apple».
10. **Две раздельные очистки** (очередь и история), обе — через подтверждающий action-sheet с деструктивным пунктом. Очистка очереди трогает **только ручную секцию**.
11. **Снэкбар после добавления кликабелен** и ведёт на экран очереди.
12. **Лимит списка ~100 предстоящих + строка «ещё N»** вместо бесконечного списка.
13. **Позиция прокрутки не сохраняется между открытиями** — при каждом открытии список прижимается к первому заголовку секции. Сохранять только при повороте.
14. **При включённом repeat скрывать автоподбор** и вместо него показывать строку-пояснение про повтор.
15. **Пустое состояние — не просто «очередь пуста»**, а подсказка, привязанная к тому, доступен ли автоподбор.
16. **Свайп-удаление: подложка с иконкой, зеркалящаяся по направлению свайпа**, обе стороны рабочие.
17. **Анонсы для TalkBack при перестановке** («переместил вверх ‹трек›»).

## Сравнение с нашим `QueueSheet.kt`

Файл: `/root/LiquidMusicGlass/app/src/main/kotlin/com/liquidmusicglass/ui/player/QueueSheet.kt` (552 строки), API очереди: `/root/LiquidMusicGlass/app/src/main/kotlin/com/liquidmusicglass/engine/PlayerController.kt` (`insertNext`, `addToQueue`, `moveQueueItem`, `removeQueueItem`, `queueFlow`).

### Что у нас уже совпало с Apple
- Играющий трек вынесен в закреплённую шапку и не является строкой списка; `moveQueueItem`/`removeQueueItem` явно игнорируют `currentIndex`.
- Список — только предстоящие (`queue.subList(currentIndex + 1, …)`).
- Перетаскивание — за ручку справа, а не long-press по строке.
- Свайп-удаление в обе стороны с порогом и учётом скорости, с анимацией «улёта» строки.
- Есть заголовок «Up Next» и пустое состояние.

### Чего у нас нет (по убыванию значимости)

| Пробел | Что у Apple | Что делать у нас |
|---|---|---|
| **Одна плоская секция** | 3 секции + история, каждая со своим заголовком | Разбить `upNext` на «Далее» (ручные) / «Продолжение ‹источник›» / «Волна». Данные для этого уже есть: `Track.source == "wave"` даёт волну, а флаг «добавлен вручную» надо завести |
| **Ручная очередь ничем не помечена** | окно `QueueSectionWindow`, метка `IS_IN_QUEUE_SECTION` | Ввести в `PlayerController` окно ручной очереди `[start, end]`; `insertNext`/`addToQueue` расширяют его, `onTrackChanged` двигает `start = currentIndex + 1`, схлопывание — сброс |
| **`addToQueue` кидает в самый конец** | «в конец» = конец ручной секции, перед остатком источника и перед волной | Переписать `addToQueue` на вставку в `end + 1` окна ручной очереди (при пустом окне — `currentIndex + 1`) |
| **`playNext` фактически = `addToQueue`** (см. `PlayerController.playNext` — вызывает `addToQueue`) | вставка строго после текущего | Использовать `insertNext` (он уже корректен) и убрать дублирующий `playNext`, либо свести его к `insertNext` |
| **Команда переноса шлётся на каждом шаге** (`onDrag` вызывает `moveQueueItem` при каждом пересечении высоты строки) | локальная перестановка, одна команда на отпускании | Двигать локальный список в состоянии Compose, а `PlayerController.moveQueueItem` вызывать в `onDragEnd` |
| **Нет ограничений дропа** | нельзя ронять в чужую секцию | После введения секций — клампить `target` границами своей секции; разрешить только «поднять из источника/волны в ручную очередь» |
| **Нет автоскролла при перетаскивании к краю** | есть, с клампом сверху | Добавить автоскролл `LazyColumn` при подходе к краю + запрет уезжать выше первого трека |
| **Нет sticky-заголовков** | закреплённый заголовок с выталкиванием | `stickyHeader` в `LazyColumn` + push-эффект по `layoutInfo` |
| **Нет истории** | секция сверху + отдельная очистка | Опционально; если добавлять — держать её выше и стартовать скролл ниже неё |
| **Нет очистки очереди** | кнопка в заголовке + подтверждение, чистит только ручную секцию | Кнопка в заголовке «Далее» → диалог → удалить только элементы окна ручной очереди |
| **Нет обратной связи при добавлении** | кликабельный снэкбар «Играет следующим» / «Добавлено в очередь» | Снэкбар с иконкой; тап открывает очередь |
| **Нет лимита и футера «ещё N»** | 100 + строка-счётчик | При длинной очереди рендерить первые ~100 и строку с остатком |
| **Скролл всегда с нуля** | прижимается к первому заголовку секции при открытии и после смены трека | Скроллить к первому заголовку секции; позицию между открытиями не хранить |
| **Нет переанкоривания при смене трека** | после DiffUtil список снова у заголовка | По смене `currentIndex` — `animateScrollToItem` на первый заголовок |
| **Нет визуального «подъёма» строки при drag** | scale ≈0.85 + elevation, 300 мс, теневые градиенты сверху/снизу | У нас есть `shadowElevation = 12f` и фон α0.06 — добавить масштаб и градиентные тени |
| **Свайп без подложки** | сплошная деструктивная подложка + иконка корзины, зеркалится | Рисовать подложку под строкой с иконкой у нужного края (сейчас только `alpha` + `translationX`) |
| **Нет режима «редактировать нельзя»** | ручка `INVISIBLE`, drag/swipe отключены | Для волны/радио отключать редактирование, ручку скрывать через `alpha 0`, а не убирать из layout |
| **Пустое состояние без контекста** | подсказка, завязанная на доступность автоподбора | «Очередь пуста» → добавить строку про волну/повтор, когда они выключены |
| **Нет строки про repeat и скрытия волны при repeat** | автоподбор исчезает, появляется пояснение | При включённом repeat прятать секцию волны и показывать строку-пояснение |
| **Нет анонсов для TalkBack** | «переместил вверх ‹трек›» | `LiveRegion` / `announceForAccessibility` после перестановки |

### Отдельно про риски в текущем коде
- В `DraggableQueueRow` смещение `acc` пересчитывается через фиксированную `56.dp` высоту строки — при появлении заголовков секций и футеров это начнёт «уезжать». Локальная перестановка (правило №6) заодно решает и это.
- `removeQueueItem(absoluteIndex(indexState.value))` вычисляет абсолютный индекс как `currentIndex + 1 + i`. Как только над списком появятся заголовки/секции, понадобится приём Apple: конвертировать позицию списка в позицию очереди вычитанием количества нетрековых строк выше.
